# 화면과 게임 연결 계획

## 기본 경계

React가 가챠, 지도, 안내, 대화창, 완료 화면을 그립니다. React Three Fiber가 같은 앱 안의 canvas에서 3D 공간을 그립니다. 게임 상태는 Zustand로 공유하되 플레이어 좌표처럼 매 프레임 바뀌는 값은 Three.js 객체/ref에서 처리합니다. Unity는 현재 필요하지 않습니다.

## 진행 흐름

가챠 → 지역 지도 → 장소 선택 → 안내(3-1) → 이동(3-2) → NPC 대화(3-3) → 완료 저장 → 완료 화면(3-4) → 다음 퀘스트. 장소의 퀘스트 4개를 완료하면 장소 완료(3-5) 후 지역 지도로 복귀합니다.

상태: idle → ready → exploring ↔ dialogue → completing → completed.
현재는 idle/ready/exploring만 작동하는 시작 골격입니다. completing/completed는 저장 기능을 연결할 때 구현합니다. 시작 클릭으로 완료 수를 올리지 않습니다. 대화 중에는 이동과 시점 조작을 멈춥니다. 목표 도착과 대화 조건이 충족됐을 때만 완료를 요청합니다.

## 맵과 상호작용

`features/game/data/places.ts`의 `map`은 현재 pending입니다. 실제 자산을 확인하면 GLB, OBJ, 스플랫 중 해당 렌더러를 연결합니다. 스플랫은 별도 렌더러와 충돌용 기하가 필요할 수 있으므로 GLB로 가정하지 않습니다. 모델 외형과 보행 경계·바닥·NPC 위치·도착 범위는 별도 데이터로 관리합니다.

기존 `../photo-map/`은 원본 맵 확인용 독립 미리보기로 유지합니다. Map_1/Map_2는 복사하지 않았으며, Marble 결과물을 받은 후 사용할 배경을 결정합니다. 원본의 구멍·왜곡이 게임 로더 추가만으로 복원되지는 않습니다.

## 데이터 저장과 서버

일시적인 카메라·대화 상태와 영구적인 퀘스트 완료·코인 잔액을 분리합니다. 서버 도입 전 시연은 별도의 localStorage 저장 모듈로 가능하나 현재는 저장·코인 기능을 구현하지 않았습니다.

서버 연동 시 사용자+퀘스트 ID로 최초 완료를 식별하고, 완료 기록과 코인 지급을 한 번에 저장합니다. 성공 응답 후 진행률과 잔액을 갱신합니다. 새로고침·재요청에 보상이 중복 지급되지 않아야 합니다. 가챠 차감과 결과 저장도 함께 처리합니다. 실제 API 경로는 백엔드 명세 확정 후 추가합니다.

음성 인식·합성·AI 판정은 대화 기능과 분리한 API 계층으로 연결합니다. 비밀 API 키는 프론트에 넣지 않습니다. VITE_* 변수는 브라우저에 공개되는 설정입니다.
