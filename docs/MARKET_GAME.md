# 전통시장 3D 게임

`/play/market`에서 Covered Korean Traditional Market 맵을 직접 걸어 다니고
상인과 한국어로 대화한다. 가챠 메인의 `전통시장 3D로 둘러보기` 또는
전통시장 장소 화면의 `3D 시장에서 플레이하기`로 입장한다.

## 조작

- W/A/S/D: 앞·왼쪽·뒤·오른쪽 이동. 방향키 위/아래: 이동, 왼쪽/오른쪽: 시점 회전.
- 마우스 또는 터치 드래그: 둘러보기. 화면의 방향 버튼을 누르고 있어도 이동한다.
- 상인의 금빛 표식에 2.4m 이내로 접근하면 `말 걸기` 버튼 표시.
- 대화와 일시 정지 중에는 이동을 멈춘다. ESC로 대화 닫기 / 일시 정지.
- `입구로 돌아오기`는 위치·시선만 복구하며 퀘스트 진행·주문·보상을 초기화하지 않는다.
- 시작 위치는 꼬마분식 쪽 매대 옆이며, 약 4.2m 떨어진 첫 상인 쪽을 바라보도록 설정한다.
  `입구로 돌아오기`도 같은 위치와 시선으로 복귀한다.

## 콘텐츠와 서버

Spring 사용자/지도 API에서 서대문구 해금 상태를 조회하고,
지역 상세의 `place`에 `전통시장`이 포함된 장소를 사용한다.
퀘스트 ID와 완료 상태는 서버 응답에서 읽으며 시드 ID를 하드코딩하지 않는다.
Q01 채소 좌판 → Q02 전집 시식 → Q03 같은 전집 흥정 → Q04 분식집 포장 주문 순서다.
맵의 상인 캐릭터는 이 데모를 위해 배치한 가상 NPC다.

`POST /api/quests/{id}/start`, `/chat`과 `GET /api/stages/{id}`를 재사용한다.
이동 좌표나 채팅 문자열로 완료를 추정하지 않고 `questCompleted`, `coins`,
`coinsEarned`와 재조회한 퀘스트 상태를 표시한다.
Q01의 도착 확인은 기존 대화 API를 통해 사용자 발화로 진행한다.
새로운 위치 인증/도착 이벤트 API를 만들지는 않았다.
Q04가 서버에서 완료되면 `Q5 · 배운 표현 복습하기` 버튼이 열린다.
Q5는 선택형 복습이며 게임 코인 보상에는 포함하지 않는다.

백엔드 또는 DB 연결이 안 되면 시장 산책만 가능하며, 퀘스트 완료나 보상을 표시하지 않는다.
지역이 잠겨 있으면 기존 서울 지도에서 가챠로 서대문구를 연 뒤 입장한다.
이 화면 진입만으로 가챠 코인을 소비하지 않는다.

## 자산과 성능

- `@sparkjsdev/spark`로 SPZ Gaussian Splatting 렌더링.
- GLB는 화면에 그리지 않고 `three-mesh-bvh`로 벽 충돌·바닥·급경사·낙하 방지에 사용.
- NPC는 Microsoft Rocketbox의 실제 인체 FBX·2048px 얼굴/옷/노멀 텍스처를 사용한다.
  팔을 편하게 내린 관절 자세, 호흡, 눈 깜빡임, 가까운 플레이어를 바라보는 동작을 적용한다.
  자산 출처·MIT 라이선스·다운로드 재현은 `public/models/npcs/README.md` 참고.
- 파노라마는 로딩/시작 화면에 사용한다. 실제 플레이는 이동 가능한 SPZ 공간이다.
- 원본 192만 스플랫을 전부 사용한다. 배포용 SPZ·GLB·PNG는 루트 원본과 바이트 단위로 같다.
- `scripts/prepare-market.py`는 원본을 그대로 복사하고 SHA-256을 대조한다. 샘플링·재인코딩하지 않는다.
- LOD를 비활성화해 스플랫을 줄이지 않는다. 픽셀 비율 최대 2, HUD 좌표 갱신 초당 약 8회,
  대형 렌더러는 게임 경로에서만 로딩한다.
- WebGL2를 지원하는 브라우저가 필요하다. 원본에 포함된 재구성 왜곡은 렌더러 설정으로 복원되지 않는다.

## 실행·검증

```sh
npm ci
npm run assets:market  # 원본에서 public/models/market 재생성할 때만
npm run check:market
npm run build
npm run dev -- --host 127.0.0.1
```

퀘스트는 BE 저장소의 MySQL과 Spring 서버가 필요하다. Vite의 `/api` 프록시는
기본 `http://localhost:8080`, Q5 `/api/review`는 `http://127.0.0.1:8001`이다.
Q5 실행은 [Q5_AGENT.md](Q5_AGENT.md) 참고.

점검 순서: 맵 로딩 → 진입 → 이동/충돌/입구 복귀 → 상인 접근 → 시작 API → 대화 API
→ 서버 미션·코인 반영 → 다음 퀘스트 → Q04 완료 → 버튼으로 Q5 진입.
실제 LLM 모드는 BE `LLM_MOCK=false` 설정이 필요하며,
mock 모드에서는 의미 평가 품질을 검증할 수 없다.
